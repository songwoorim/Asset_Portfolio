# 자산 포트폴리오 통장 (Asset Portfolio)

개인용 투자 포트폴리오 대시보드. 단일 HTML 파일 하나(`index.html`)로 완결되며 GitHub Pages로 호스팅됩니다.

**🔗 배포 사이트: https://songwoorim.github.io/Asset_Portfolio/**

---

## 개요

해외주식(14종목) · ISA(2종목) · 연금저축(2종목) · 예수금(USD+KRW) 4개 계좌를 통합 추적합니다.
실시간 시세는 Finnhub(무료 키) + open.er-api(환율, 무료·키 불필요)로 클라이언트에서 직접 fetch 합니다.

- **설계 기준**: iPhone 16 Pro 모바일 우선
- **디자인 언어**: Apple 스타일 (화이트/파치먼트 + Action Blue `#0066cc`)
- **빌드 불필요**: 별도 번들러/서버 없이 `index.html` 하나로 동작

## 화면 구성 (하단 고정 탭 5개)

| 탭 | 내용 |
|---|---|
| **홈** | 표지(총자산·당일/총수익 칩·자산배분 그리드) → 종목별 보유비중 → 수익률 히트맵 → 시장지수 → 환율 → 통화노출 |
| **손익** | 수익 현황 → 자산 추이(스크럽 그래프) → 벤치마크 비교(vs S&P500) → 월간·연간 리뷰 → 실현손익 |
| **보유** | 계좌별 보유 종목(해외주식/ISA/연금저축) → 예수금 → 자산배분 도넛 → 종목별 비중 → 섹터·테마 → 종목별 손익률 |
| **리밸런싱** | 리밸런싱 제안 → 체크포인트(17행 슬라이더) → 양도세 시뮬레이터 → What-if 매수 시뮬레이터 → 진단 |
| **이력** | 거래이력(198건, 필터) → 종목 뉴스 |

## 변경 이력

### "기간별 손익" 전면 재점검 — 계산 기반을 자체 시계열로 교체 (2026-08-08)
사용자가 "전체" 범위에서 누적손익률 **+915.8%** 를 발견해 섹션 전체를 다시 점검. 서로 얽힌 버그 3건을 확인하고 계산 기반 자체를 바꿔 해결했다.

- **버그 1 — 누적손익률 915%**: 분모로 "기간 첫날 평가액"을 썼는데 "전체"의 첫날은 2021년(자산 291만원)이라 26,652,621÷2,910,238 = 915%가 나왔음. 기간이 길어 그 사이 원금이 크게 늘면 이 방식 자체가 성립하지 않고, 기간마다 분모 기준이 달라 비교도 불가
  → **시간가중수익률(TWR, 일별 수익률 누적곱)** 으로 교체. 입출금·원금 증감에 영향받지 않는 표준 방식. 전체 기간 **+915.8% → +120.0%** (5.5년 실적으로 타당한 수준)
- **버그 2 — 평가액은 같은데 당일손익이 다른 행**(08/07 +2,834,619 / 08/08 -1,882,646, 평가액 둘 다 84,498,364): 직전 세션에 원가(CS)만 TXL로 재계산하고 평가액(AS)은 옛 정적 데이터를 그대로 써서 **두 배열의 출처가 어긋난 것**이 원인. 매수한 날 원가만 뛰고 평가액은 안 움직여 가짜 손익이 발생. 애초에 HIST.a/HIST.c 자체가 서로 다른 방식으로 만들어져 있었음(2021년 첫날 원가 13.7만원 / 평가액 291만원 = 수익 277만원이라는 불가능한 값)
- **버그 3 — 전량매도 종목 누락**: 현재 보유(HOLDINGS) 기준으로만 계산해 중간에 정리한 종목이 빠졌음
- **해결 — `plBuildSeries()` 신규**: 이 섹션은 HIST.a/HIST.c를 더 이상 쓰지 않고, **평가액·원가를 모두 TXL(거래이력)에서 같은 방식으로 직접 계산**한다. 출처가 하나라 서로 어긋날 수 없음. 티커는 "한 번이라도 거래한 전 종목"(18개) 기준이라 전량매도 종목도 포함. 가격은 KIS 실측 종가가 있으면 그것을, 없으면 `priceAt()` 보간값을 사용. 날짜별 환율은 한 번만 계산해 재사용하고 티커별 거래·종가를 포인터로 훑어 O(일수×종목)로 처리(전체 1969일 재계산 156ms). 결과는 캐시하고 실측 종가가 새로 들어오면 `plInvalidateSeries()`로 무효화
- **중복 제거**: 직전 세션에 만든 `ensureGapFillPrices()`(최근 24일치만 조회)를 폐기하고, 수익현황 탭이 이미 쓰던 **`ensureHistPrices()`를 재사용**하도록 정리 — 이 함수가 이미 연초부터 전 종목 실측 종가를 받아오므로 별도 조회가 불필요했음(API 호출도 감소). `reconstructGapAS()`는 자산추이 차트 정확도 보정용으로만 남김
- **AS/CS 전역 배열은 이 섹션과 분리**: 기존 화면(자산추이·벤치마크 등)의 회귀 위험을 피하려고 섹션 계산을 독립시켰음
- 검증(Node VM 샌드박스, 실제 데이터):
  - 5개 범위(1주/1개월/3개월/올해/전체) × 2개 단위(일별/월별) = **10개 조합 전부 NaN·Infinity 0건**
  - **일별과 월별의 누적손익·누적손익률이 모든 범위에서 정확히 일치** (계산 일관성 확인)
  - 오늘 평가액이 실시간 `grandTotal()`과 **6,979원(0.008%) 차이**로 수렴 (수정 전 286만원 차이)
  - `grandTotal()` = 82,886,595.444원, 앵커값 일치
- **남은 한계**: 실측 종가를 확보하지 못한 과거 구간은 여전히 `priceAt()` 보간값이라 일별 변동이 실제보다 매끄럽게 보일 수 있음(Worker 페이지 한도 확장이 필요한 사안으로, 아래 항목대로 보류 상태). 현금은 일자별 추적이 불가해 현재 잔액으로 근사. 이 내용은 섹션 하단 설명 문구에도 명시함

### "전체"(2021년~) 범위 완전 정확화는 보류 결정 (2026-08-08)
- CS(원가) 재계산 버그를 고치던 중, "전체" 범위에서 평가액(AS)이 부자연스럽게 매끈한 직선 패턴으로 움직이는 걸 추가 발견(거래일 사이를 `priceAt()`으로 직선 보간하기 때문 — 실제 종가가 아님)
- 근본적으로 고치려면 Worker(`kis-proxy-worker.js`)의 과거시세 조회 페이지 한도(현재 4페이지=약 400영업일≈1.6년)를 5.5년치(약 16페이지)로 늘리고 **Cloudflare에 재배포**해야 하며, 최초 로딩 시 API 호출이 크게 늘어 30초~2분 정도 걸릴 것으로 예상됨
- 사용자 판단: 과거(2021년 등) 이력은 자주 안 보고, 최근 날짜 정확도가 중요 → **이 큰 작업은 보류**하기로 결정. 최근 구간 정확도는 이미 아래 두 가지로 충분히 커버됨:
  1. 원가(CS) 전체 재계산 — TXL 기반, 전 기간에 걸쳐 100% 정확
  2. 최근 24일 gap-fill — 실제 KIS 종가 기반
- 필요해지면 나중에 다시 진행하기로 함(Worker 페이지 한도 확장 + 프론트 전체 재구성 로직은 설계까지는 논의됨, 코드 미반영)

### "기간별 손익" 원가(CS) 히스토리 근본 오류 수정 — 계좌 개설 초기부터 부풀려져 있던 문제 (2026-08-08)
- **증상**: "손익 탭 → 기간별 손익"의 "올해" 누적손익이 실제 "수익 현황" 탭 수치(+3,319,002원/+5.7%)와 크게 다름(+8,146,407원/+14.1%)
- **원인**: 정적으로 박혀있는 원가(HIST.c) 데이터가 **계좌 개설 초기(2021-02)부터 이미 실제보다 부풀려져 있었고** 시간이 갈수록 격차가 커지는 구조였음. 첫 거래 이틀 뒤 시점(TXL 기준 정확한 원가는 228,112원)에 정적 데이터는 3,023,043원(13배)으로 박혀있던 것을 확인 — HIST를 처음 만들 때의 산정 방식이 TXL과 어긋났던 것으로 추정(정확한 최초 원인은 불명)
- **수정**: `regenerateCS()` 신규 추가 — 페이지 로드마다 TXL(거래이력) 199건을 티커별로 한 번만 정렬한 뒤 날짜 포인터를 앞으로만 이동시키며 전체 기간(1969일)의 원가를 처음부터 다시 계산해 CS 배열을 덮어씀. 네트워크 불필요, 반복 정렬 없어 가볍다(로드 시 약 130ms 추가)
- 검증: 재계산된 값이 TXL 기반 정확한 값과 3개 시점(2021/2025/2026)에서 완전 일치. "올해" 기간별 손익 재계산 결과 **+3,307,815원(+5.71%)** — 실제 화면(+3,319,002원/+5.7%)과 거의 정확히 일치(만원 단위 차이는 환율 근사 방식 차이로 추정). `grandTotal()` = 82,886,595.444원, 앵커값과 일치(이 값은 CS 히스토리와 무관하게 실시간 계산되므로 영향 없음)

### "기간별 손익" 최근 구간 실측 재구성 — flat 이월 버그 근본 수정 (2026-08-08)
- **증상**: "기간별 손익" 표에서 최근 며칠~몇 주가 당일손익 +0/0.0%, 평가액도 전부 동일 금액으로 나란히 찍히는 문제 발견(사용자 리포트)
- **원인**: 앱을 실제로 연 날만 로컬에 스냅샷이 저장되는 구조(`recordTrendPoint()`/`TREND_KEY`)라서, 앱을 안 연 날은 `loadFutureSnaps()`가 직전 값을 그대로 복사(flat carry-forward)해 채워 넣고 있었음 — 계산 로직 버그가 아니라 데이터 소스 자체가 비어있던 것
- **수정**: 기존에 손익현황 탭 계산(`computePeriodPL`)용으로 이미 구축돼 있던 인프라를 재사용해 최근 구간을 실측 재구성
  - `HIST_PRICE_CACHE`/`/hist/domestic`·`/hist/overseas` — KIS 실제 과거 종가
  - `stateAt(tk, date)` — TXL(거래이력) 재생으로 특정 과거일의 보유수량·평균원가 복원
  - 새 함수 `ensureGapFillPrices()`(HIST 정적 데이터 마지막 날 이후~오늘까지 현재 보유 종목의 실제 종가를 Worker에서 조회, 캐시 저장) + `reconstructGapAS()`(그 실측 종가로 AS/CS 배열의 해당 구간을 다시 계산)
  - 오늘 원가(CS)도 `investedCost()` 실시간 값으로 맞춤(AS는 기존 `syncTrendToday()`가 이미 처리)
- **알려진 한계**(정확도 저하 요인, 문서화해둠):
  - 이 구간 안에서 완전히 정리(전량매도)해 지금은 보유 목록에 없는 종목은 재구성에서 빠짐(드문 경우로 판단해 범위 밖으로 둠)
  - 현금은 일자별 변동 추적이 불가해 "현재 현금"으로 근사(투자원금·평가액 쪽 정확도가 훨씬 중요해서 우선순위상 수용)
  - 환율은 앱 전체와 동일하게 분기별 근사 앵커 사용(일별 정밀 환율 데이터 없음)
  - 실제 KIS 종가 조회에 실패하면(네트워크 오류 등) 조용히 실패하고 기존 carry-forward 방식으로 자동 폴백 — 화면이 깨지지 않음
- 검증: Node VM 샌드박스에 실제 파일 전체를 로드하고, 가짜 KIS 종가로 24일 gap을 시뮬레이션 — 수정 전 8일 내내 동일 금액으로 고정되던 게 수정 후 날마다 정상적으로 변동하는 것 확인. 오늘 원가도 `investedCost()`와 정확히 일치. `/hist/*` 실제 네트워크 호출 자체는 작업 환경에 인터넷이 없어 테스트 불가 — **실제 배포 사이트에서 최초 1회 확인 필요**. `grandTotal()` = 82,886,595.444원, 앵커값과 일치

### 손익 탭 — "기간별 손익" 섹션 신규 추가 (2026-08-08)
- **위치**: 자산추이 바로 다음(수익현황 → 자산추이 → **기간별 손익** → 벤치마크 → 월간·연간리뷰 → 실현손익). 그래프(자산추이)로 대략 흐름을 보다가 바로 아래서 정확한 일별·월별 숫자를 확인하는 자연스러운 동선으로 배치
- **계산 방식**: `(평가액-원금)`의 일별/월별 변화분 = 입출금(매수·매도) 영향을 제외한 순수 투자손익. 기존 `AS`/`CS`(자산·원금 일별 시계열) 재사용, 새 데이터 소스 불필요
- **기간 선택**: 1주/1개월/3개월/올해/전체/직접설정(달력) 칩 + 일별/월별 토글
- **누적 기준**: 화면에서 고른 기간의 **첫날 대비** 누적(달력을 바꾸면 누적도 그 기간 기준으로 다시 계산됨) — 연초 고정이나 최초 투자일 기준 등 다른 방식도 검토했으나, "지금 보고 있는 기간 안에서 얼마 벌었는지"가 제일 직관적이라 이 방식으로 확정
- **컬럼**: 일자/월 · 당일(금액+%, 색상 강조) · 누적(금액+%, 회색 — 당일과 색이 겹치지 않도록 의도적으로 무채색 유지) · 평가액(굵게 강조)
- **디자인 반복**: 카드형 vs 표형 비교 → 표형 선택(여러 날짜를 세로로 비교하기 편해서) → 가로 스크롤이 걸려서 컬럼 6개를 3~4개로 압축 → 라이트모드 확인까지 여러 라운드 목업 검토 후 확정
- **버그 수정 2건**:

### 스크롤 등장 효과 개선 (한번에 다 나오던 문제 수정)
- 기존엔 페이지 전체 18개 섹션을 한 번에 관찰(observe)해서, 홈 탭처럼 섹션이 촘촘히 붙어있으면 스크롤을 살짝만 해도 여러 개가 동시에 감지되어 "한번에 다 나오는" 것처럼 보이는 문제가 있었음
- **패널 단위로 분리**: `revealPanel(panelName)` 함수가 해당 탭(`data-panel`)의 섹션들만 새로 관찰하도록 재작성. `threshold`/`rootMargin`도 더 엄격하게 조정해서 실제로 화면에 충분히 들어와야 등장하도록 수정
- **탭 전환 시 재생**: 하단 탭바를 눌러 다른 화면으로 이동하면 그 탭의 섹션들을 "아직 안 나타난 상태"로 리셋하고 다시 관찰 시작 — 같은 탭을 반복해서 오갈 때마다 등장 효과가 매번 재생됨. 단, 같은 탭 안에서 스크롤을 위아래로 반복하는 것만으로는 재생되지 않음(한 번 나타난 섹션은 그 탭 안에 머무는 동안엔 유지)

### 인터랙션 효과 7종 추가
확인해보니 4개(카운트업 확장/스케일 눌림/실시간 펄스/새로고침 체크)는 이미 이전에 반영돼 있었고, 이번엔 나머지 3개를 마무리했습니다.
- **세그먼트 필 슬라이드**: 수익현황 기간탭(`#pnlTabs`)·자산추이 기간탭(`#trPeriods`)·종목별 보유비중 스코프탭(`#swSeg`) 3곳에 공용 헬퍼(`initSegPill()`/`positionSegPill()`) 적용 — 탭을 누르면 흰 배경이 순간이동 대신 옆으로 미끄러지듯 이동. 처음엔 숨겨진 탭(`display:none`) 안에 있어 폭 계산이 0으로 나오는 문제가 있어, 하단 탭바 전환 시 순간이동 모드(`instant`)로 위치를 재보정하도록 처리
- **도넛 그려지는 애니메이션**: 공유 함수 `donutSVG()`(자산배분·섹터비중에서 사용)에 이미 마련돼 있던 `.donut-arc-draw`/`data-dash` 마크업에 CSS 트랜지션 규칙을 추가하고, 두 호출부(`renderAllocDonut`, `renderSectorAlloc`)에서 `animateDonutArcs()`를 실제로 호출하도록 연결. 종목별 보유비중 도넛(`swRenderDonutBase`)은 개별 `<path>` 구조라 stroke-dasharray 방식 대신 opacity 페이드인 + 항목별 미세 딜레이로 구현 — 기존 클릭 시 팝아웃(transform 기반)과 충돌하지 않도록 트랜지션 속성을 분리
- **스크롤 등장 효과**: `.page.collapsible` 18개 섹션에 `IntersectionObserver` 기반 1회성 fade-in-up 적용. JS가 `.scroll-ready` 클래스를 붙여야만 opacity:0으로 시작하는 구조라, JS 실패 시에도 콘텐츠가 영구히 숨겨지지 않도록 안전장치를 이중으로 마련(클래스 미부여 시 항상 보임 + 3초 타임아웃 강제 표시)

- **총자산(coverTotal) 카운트업 애니메이션**: 새로고침 시 이전 값에서 새 값까지 부드럽게 롤링되며 안착(ease-out, 도중에 값이 또 바뀌어도 0으로 리셋되지 않고 이어서 전환)

### 예수금 리디자인 (전체 현금 통합형)

- 모든 금액·비중은 `CASH`/`ISA_CASH`/`FX`에서 실시간 계산 (하드코딩 없음)

- **스코프 탭 3개 신규**: 전체 자산 / 해외주식 / 국내 ETF — 예수금까지 포함한 전체 그림부터 계좌별 세부 비중까지 좁혀볼 수 있음
- **도넛 세그먼트 클릭 인터랙션**: 조각이나 리스트를 탭하면 해당 종목이 상단 상세(로고·이름·비중%·평가액·수익률)로 전환. 선택된 조각은 `transform: translate()`로 부드럽게 튀어나옴(스프링 이징) — 매번 SVG를 다시 그리지 않고 기존 엘리먼트의 transform만 갱신해서 실제로 애니메이션이 재생되도록 구현
- **숫자 카운트업 애니메이션**: 종목 전환 시 %가 이전 값에서 새 값으로 부드럽게 굴러가며 바뀜 (ease-out, 320ms)
- **선명한 팔레트 신규 도입**: 기존 파치먼트 톤 대신 블루→핑크→틸 계열의 선명한 색상 세트(`SW_PAL`)를 이 섹션 전용으로 사용 — 19개 조각까지 늘어나는 "전체" 탭에서도 구분이 잘 됨. 종목 로고는 기존 3단계 우선순위(Simple Icons → CUSTOM_LOGOS → 컬러 이니셜) 그대로 재사용
- **인사이트 영역**: "최대 비중 vs 최소 비중" 히어로 카드 + "상위 3개 집중도"·"핵심 포지션(5% 이상 종목 수)" 통계 칩 2개. **show/hide 토글**로 접고 펼 수 있으며 기본값은 열림
- **리스트 자체 스크롤 분리**: 종목 리스트만 최대높이 252px의 자체 스크롤 박스로 분리해서, 리스트를 내려도 위쪽 도넛·인사이트는 항상 고정되어 보임 (기존 "전체보기" 접기/펼치기 버튼은 필요 없어져서 제거)
- 스크롤 박스 내 가로 스크롤 버그 수정 — 리스트 행의 호버 배경 확장용 음수 마진이 스크롤 박스 밖으로 삐져나가던 것을 `overflow-x:hidden`으로 차단

### 실현손익(`#sec-realized`) 리디자인
- 히어로 카드로 누적 확정 손익을 크게 표시 (금액 색상 `var(--stamp-red)`)
- **통계 칩 3종** 추가: 총 거래 건수 / 승률 / 건당 평균 실현손익 (모두 기존 `REALIZED` 배열에서 자동 계산)
- **최고 실현 거래 스포트라이트** 카드 신규: 가장 큰 실현손익을 낸 거래를 로고와 함께 강조
- 기존 단순 리스트를 **거래 타임라인**(세로 점선 + 종목 로고 마커)으로 전환, 최고 실현 거래는 타임라인에서도 빨간 링으로 한 번 더 강조

## 알려진 버그 패턴 (재발 방지 메모)

- **스크립트 실행 순서** — HTML 요소를 `<script>` 태그보다 뒤에 넣으면 해당 요소를 참조하는 이벤트 바인딩이 전부 무효화됨. 새 DOM은 항상 `<script>` 앞에 배치할 것
- **CSS 중복 규칙** — 같은 선택자를 리팩터링 중 남겨두면 나중 규칙이 이전 규칙을 덮어써서 의도치 않은 스타일이 되살아남. 큰 리디자인 후엔 `grep -c ".foo{"`로 중복 정의 확인
- **`data-panel` 미부여** — 새 섹션 추가 시 `data-panel` 속성을 빠뜨리면 탭 전환과 무관하게 항상 노출됨
